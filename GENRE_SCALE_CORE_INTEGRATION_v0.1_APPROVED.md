# 1. Executive Summary

이번 Integration의 가장 중요한 결론은 다음과 같다.

1. **현재 51개 Genre Scale Handoff 중 신규 독립 GSC로 승격할 가치가 충분한 항목은 `0개`다.**
   - 이는 Cross-layer Risk가 없다는 뜻이 아니다.
   - 오히려 대부분의 Risk가 이미:
     ```text
     Genre Parent
     +
     Scale Parent
     +
     SCALE_HANDOFF
     ```
     로 충분히 발견되고 동일한 Reviewer Action까지 도달한다는 뜻이다.

2. **기존 3개 GSC도 독립 Core로 유지할 필요성이 약하다.**
   - `GSC-DECK-SOLO-001` → `RETIRE_AS_INDEPENDENT_GSC_RECOMMENDED`
   - `GSC-MGMT-SOLO-001` → `RETIRE_AS_INDEPENDENT_GSC_RECOMMENDED`
   - `GSC-DEDUCT-SOLO-001` → `RETIRE_AS_INDEPENDENT_GSC_RECOMMENDED`
   - 단 Canonical 원본 Status는 이번 문서에서 변경하지 않는다.

3. 기존 세 GSC 중 Management가 가장 강한 Cross-layer 표현을 가지고 있지만, 엄격한 Reviewer Difference Test를 통과하지 못했다.
   - `GC-MGMT-014 — Responsibility Level`
   - `GC-SIM-001 — Selective Simulation` (Simulation이 실제로 routed될 때)
   - `SC-SOLO-002 — Visible Scope ≠ Production Scope`
   - `MGMT-001/002`
   만으로:
   > Player Responsibility Level을 Scope Cut Boundary로 사용한다.
   는 동일 Reviewer Action에 도달할 수 있다.

4. 따라서 **GSC Layer는 삭제할 필요는 없지만, 현재 Canonical Knowledge에서는 비어 있어도 정상인 얇은 Optional Layer**로 보는 것이 가장 일관적이다.

5. 가장 많은 Handoff가 환원되는 Scale Parent는:
   - **`SC-SOLO-002 — Visible Scope ≠ Production Scope`**
   이다.
   - 51개 Risk Tag에서 `QA`가 **32개**, `Content` **21개**, `Logic` **17개**, `Technical` **13개**로 반복된다.
   - 대부분은 별도 GSC보다 SC-SOLO-002의 Production Cost Axis specialization이다.

6. 두 번째로 중요한 Scale Parent는:
   - **`SC-SOLO-003 — Common Grammar is a Content Multiplier`**
   이다.
   - Deck / Roguelike / Simulation / 일부 RPG·Action의 data/reuse Handoff는 공통 Grammar가 Unique Production 비용을 줄이지만 QA/Balance/Regression을 남긴다는 Boundary로 환원된다.

7. Cross-Genre Scale Cluster 5개를 분석했지만 모두 새 GSC Cluster가 아니다.
   - Interaction Matrix Explosion → `SC-SOLO-002` 하위 Production Risk
   - Authored Logic Density → `SC-SOLO-002` + Genre Handoff
   - Specialist-gated Presentation → Scale Cost Axis / Externalization Router
   - AI / Simulation Infrastructure → Technical / Specialist Scale Cost
   - Tooling ROI → Scale Tooling Axis
   Cluster 자체를 Core로 승격하지 않는다.

8. **Solo-specific Mechanism은 Risk의 종류보다 Risk의 Production Consequence를 바꾼다.**
   - No Parallel Capacity
   - Single-owner Dependency
   - Manual Regression Ownership
   - Specialist Gap
   - Limited Iteration Throughput
   - Tooling Opportunity Cost
   - External Integration Ownership
   즉 Deck QA가 Solo에서 다른 종류의 QA가 되는 것이 아니라, 같은 QA Matrix가 Solo의 단일 ownership / throughput 제약에 더 직접적으로 부딪힌다.

9. Micro에서 가장 크게 완화될 수 있는 것은:
   - asset/content production
   - specialist-gated presentation
   - 독립 QA lane
   - code/art 병렬화
   이다.

10. Micro에서도 거의 완화되지 않는 것은:
    - Multiplicative Interaction Complexity
    - State / Logic dependency
    - shared architecture
    - regression definition
    - core design ownership
    - acceptance / integration responsibility
    이다.
    인원이 늘어도 조합 수 자체가 사라지지는 않는다.

11. Externalization이 비교적 쉬운 영역은:
    - VO
    - standalone audio
    - 일부 illustration / equipment art
    - 일부 VFX/SFX
    - localization production
    이다.
    하지만 Specification / Acceptance / Integration / Regression ownership은 내부에 남는다.

12. Internal Ownership이 특히 강하게 필요한 영역은:
    - deduction clue logic
    - reactive narrative state logic
    - simulation dependency / save architecture
    - strategy / simulation AI behavior
    - quest × build architecture
    - action hitbox / input / feel integration
    - deeply coupled production tooling
    이다.

13. `RPG × Solo`와 `Action × Solo`는 신규 GSC를 만들기에 특히 Evidence가 약하다.
    - RPG / Action Genre Baseline 자체가 `Provisional = NONE`.
    - Handoff는 유용하지만 독립 Cross-layer Rule 승격에는 Direct Production Evidence가 부족하다.

14. `STRAT-005 Multiplayer Balance Multiplier`는 현재 Integration Scope 밖 Evidence다.
    - `EVIDENCE GAP / FUTURE RESEARCH`
    - Small/Mid+/competitive production에 대한 추가 자료 없이 Solo GSC로 만들지 않는다.

15. 이번 Integration이 제안하는 장기 Canonical 구조는 다음과 같다.

```text

↓
Genre

```

현재는:

```text

```

가 정상 결과다.

16. **Universal Core Consolidation으로 바로 넘어가지 않는다.**
    - 먼저 짧은 `Canonical GSC Consolidation / Source Sync`를 수행한다.
    - 목적:
      - 기존 3개 GSC의 retirement recommendation을 Canonical metadata에 반영
      - 독립 GSC → `Routing Specialization / Parent + Handoff`로 이동

# 2. Genre × Scale Layer Purpose

GSC Layer의 목적은 Genre와 Scale을 곱해 Rule 수를 늘리는 것이 아니다.

정의:

> **Genre-specific Mechanism과 Scale-specific Constraint가 결합해 Parent Layer 어느 한쪽으로도 환원되지 않는 새로운 Reviewer Decision을 만들 때만 존재하는 최소 Cross-layer Knowledge Layer.**

다음은 GSC가 아니다.

```text
Genre Risk
+
Solo에서는 더 힘듦
```

진짜 GSC는:

```text
Genre Mechanism
×
Scale Constraint
↓
새로운 Cut Boundary / Production Decision
```

이어야 한다.

# 6. Reduction Test

모든 Existing / New Candidate에 먼저:

```text
Genre Parent
+
Scale Parent
+
Relevant Handoff
```

를 적용한다.

## REDUCIBLE

Parent 조합으로:
- 같은 Risk를 발견하고
- 같은 Cut Boundary를 찾고
- 같은 Production Action을 제안

할 수 있다.

별도 GSC 불필요.

## NON-REDUCIBLE

Parent만으로는:
- Cross-layer Mechanism을 놓치거나
- 다른 권고를 내림.

Promotion Gate로 이동.

## 9.2 Management × Solo

### `GSC-MGMT-SOLO-001 — Simulate the Player’s Job, not the Whole World`

**Canonical:** `PROVISIONAL CORE`  
**Integration Decision:** `RETIRE_AS_INDEPENDENT_GSC_RECOMMENDED`

### Parent

- `GC-MGMT-014 — Micromanagement Must Match the Player's Responsibility Level`

Management는:
- entity
- state

Solo에서는:
- no parallel capacity
- UI state
- QA
- tooling
이 즉시 Scope problem이 된다.

따라서:

> Player Responsibility Level을 Scope Cut Line으로 삼는다.

는 표현은 매우 유용하다.

### Genre Counterfactual

부분 FAIL.

이 원칙은:
- Simulation
- Job Fantasy
- 일부 Strategy
에서도 적용 가능하다.

### Scale Counterfactual

부분 FAIL.

Management design 자체에서도:
> Responsibility Level 아래의 micromanagement를 제거한다
는 원칙은 Solo가 아니어도 유효하다.

Solo는 이 Cut의 urgency를 높인다.

### Reviewer Difference Test

FAIL.

다음 Parent 조합으로 동일 Action에 도달한다.

```text
GC-MGMT-014
+
GC-SIM-001 (if applicable)
+
SC-SOLO-002
+
MGMT-001/002
↓
Remove states / entities / controls below the player's responsibility level first.
```

### Recommendation

독립 GSC보다:

```text
ROUTING SPECIALIZATION:
Responsibility Level as Scope Cut Boundary
```

가 더 정확하다.

이 표현은 Reviewer Runtime에서 강하게 보존할 가치가 있다.

# 25. Genre Promise Preservation Audit

Scope Cut은 Production Cost만 낮추고 Genre 구매 이유를 파괴할 수 있다.

따라서 Cut 우선순위:

```text
1. Redundant Unique Logic
2. Low-value State Combination
3. Presentation Variant
4. Low-value Authored Content
5. Parallel System
6. Core Genre Verb
```

## Genre-specific Preservation

| Genre | Preserve First | Cut Before Core Promise |
|---|---|---|
| Deckbuilding | contextual value / build identity / synergy decisions | duplicate cards, redundant effect families |
| Management | priority conflict / diagnosis / reprioritization | state below responsibility level, redundant entities |
| Roguelike | run variation / adaptation / path dependence | unlock bloat, low-impact modifiers |
| Deduction | inference ownership / logical reachability | duplicate clues, redundant scene detail |
| Narrative | persistent state / meaningful recontextualization | branch variants without lasting state difference |
| Strategy | future option / re-evaluation / objective value | map breadth, redundant unit/ability variants |
| Simulation | experience-relevant causality | realism detail with no downstream effect |
| RPG | character formation / role expression | unsupported classes/items/companions before core role |
| Action | direct control / threat-feedback loop | presentation variants and enemy/weapon breadth before core verbs |
